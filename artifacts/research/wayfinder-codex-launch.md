# Codex launch contract — research input cho decision 24

Ngày đọc: 2026-10-12. Phạm vi: adapter Codex ACP **2.2.2**, backend package **0.160.1**, macOS; giải thích nguồn của failure trong confinement R4 và trả input cụ thể cho prototype 18. **Research đã thực hiện; candidate chưa chạy, chưa xác nhận confinement có auth.** Không mở actual user config, auth.json, keychain hoặc managed preferences; không initialize adapter, login, session, prompt, model call, policy override hoặc thay profile/account.

## Kết quả chính

Lỗi `Failed to synchronize managed preferences` có call site chính xác trong public source tag `rust-v0.160.1`: `CFPreferencesAppSynchronize` cho domain `com.openai.codex` trả 0. Tuy nhiên source tạo `io::Error::other`, không chứng minh rằng một syscall cụ thể hay riêng một Mach service bị deny. Log R4 có thêm `Operation not permitted`; chưa xác định nguồn EPERM đó. Mở rộng toàn process tree sang cfprefsd vì suy đoán sẽ làm mất ranh giới đọc: source sandbox của cùng tag cảnh báo preferences IPC có thể vượt filesystem roots. [Backend macOS loader](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/config/src/loader/macos.rs#L136), [policy preferences](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/sandboxing/src/seatbelt_preferences_policy.sbpl), [actual R4 findings](https://github.com/Riso-application-factory/zed-ai-crew/issues/18#issuecomment-6110718104).

Nguồn hiện có cho phép xây candidate **trusted native orchestrator/auth/policy + separately confined tools**, nhưng adapter pin chưa cung cấp sẵn một complete auth/policy broker cho Crew. Research không đủ để tuyên bố candidate khả dụng end-to-end, và không được coi `initialize` thành công là credential isolation. Giữ nguyên route/account và managed requirements; trở lại prototype với failure criteria cụ thể dưới đây.

## Ranh giới native runtime và untrusted execution

Adapter launches backend bằng `spawn` với `env ?? process.env`; restart đi cùng spawner. Không có env scrub riêng tại đây. Startup logger ghi config/default-auth-request khi logging bật; không đặt secret-bearing `DEFAULT_AUTH_REQUEST` rồi coi logs an toàn. [launch connection](https://github.com/agentclientprotocol/codex-acp/blob/v2.2.2/src/CodexJsonRpcConnection.ts#L34), [entrypoint](https://github.com/agentclientprotocol/codex-acp/blob/v2.2.2/src/index.ts#L97).

Tag config manager có non-strict fallback phục vụ configuration repair, và local-policy failures được mô tả là block traffic. Vì vậy `using defaults` trong stderr chưa đủ kết luận native engine đã bypass policy hoặc chạy task; Crew cần kiểm effective policy/admission cụ thể. Không lấy internal fallback/override làm API để né policy. [startup/default config handling](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/app-server/src/config_manager.rs#L319). Adapter logging path có `APP_SERVER_LOGS` tới `app-server.log`, riêng với backend `log_dir`; fixture cần kiểm cả hai. [adapter logger](https://github.com/agentclientprotocol/codex-acp/blob/v2.2.2/src/Logger.ts).

Pin backend shell policy default là inherit **All**, `ignore_default_excludes=true`, không có include/exclude patterns; một số native control tokens được hard-scrub riêng, không phải mọi API/GitHub token. Explicit allowlist vẫn cần và phải kiểm actual shell/profile behavior. [default policy](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/protocol/src/config_types.rs#L240), [env population/scrub](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/protocol/src/shell_environment.rs).

MCP env là pathway khác: default names cộng configured `env_vars`/literal overrides; không dùng cùng mọi shell filters. Local stdio MCP là child của orchestrator; executor mode là path khác, có descriptor policy riêng. Không suy shell sandbox giới hạn mọi local MCP hoặc hook. [MCP env](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/rmcp-client/src/utils.rs#L16), [MCP launch placement](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/rmcp-client/src/stdio_server_launcher.rs).

ACP session modes có workspace-write/read-only và full-access; workspace-write không tự đảm bảo chỉ đọc trong workspace. Backend seatbelt code có full-disk-read branch và unreadable roots. Tag requirements có filesystem `deny_read`, nhưng actual effective policy và launcher path chưa kiểm. [ACP modes](https://github.com/agentclientprotocol/codex-acp/blob/v2.2.2/src/AgentMode.ts), [seatbelt builder](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/sandboxing/src/seatbelt.rs#L985), [filesystem requirements](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/config/src/config_requirements.rs#L678).

Source preference policy cho unrestricted reads allow cfprefsd daemon/agent, POSIX shared-memory prefix `apple.cfprefs.`, user-preference-read. Restricted-read profiles bỏ policy đó bởi preference IPC có thể đọc ngoài roots. Đây là chính **trade-off**, không phải allowlist launch-level được khuyến nghị. Child inheritance của outer Seatbelt khiến quyền thêm cho auth process cũng tới children; cần separate privilege boundary hoặc native launcher thực sự thu hẹp quyền, không chỉ prompt/approval. [native preference policy](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/sandboxing/src/seatbelt_preferences_policy.sbpl), [base child policy](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/sandboxing/src/seatbelt_base_policy.sbpl).

Không thấy implementation thay native command/file execution bằng tất cả ACP client tools trong pin; các ACP fs schemas/capability flags không đủ làm bằng chứng. Backend dynamic-tool/external-sandbox schemas cũng không phải execution broker đã tích hợp vào adapter. Native subagent threads/MCP/hooks/tool runtime phải nằm trong probe matrix riêng; không suy tất cả là OS subprocess chia cùng boundary.

## Candidate và return criteria cho prototype 18

1. **Khuyến nghị investigate:** giữ trusted native orchestrator nhận đúng auth/forced requirements; giới hạn children bằng explicit effective read/write/network policy, env allowlist và descriptor hygiene. Giữ GitHub PAT/App key/token ở Crew gateway, không đưa vào adapter tree. Admission fail closed khi load/refresh requirements hoặc child confinement không chứng minh được. Đây là candidate cần native tool/MCP/hook execution coverage, chưa một contract hoàn chỉnh cho cả ba adapter.
2. **Conditional backend seam:** nếu candidate đầu không tách được auth IPC khỏi untrusted runtime, evaluate supported host-owned external-auth seam và confined executor. Adapter pin hiện thiếu forwarding/refresh; đó là engineering gap có nguồn, không cần hỏi Human cho phép bypass. No policy overrides; preserve same account/workspace/route/data admission. Không chọn API proxy/custom provider như thay thế tự động.
3. **Không chấp nhận làm resolution:** broad allow `.codex` hoặc cfprefsd cho toàn tree; ignore managed requirements; blank internal overrides; copy real auth.json vào worker scratch; secret env/FD; full-access mode; đổi API billing/route ngầm; claim native defaults đủ.

Concrete probe inputs, **chưa executed**:

- Bắt đầu credential-free synthetic fixtures: `CFPreferencesAppSynchronize` domain tổng hợp cho dependency calibration; actual `com.openai.codex` policy-reading chỉ trong authorized admin/native path với output metadata đã lọc, không preference payload. Tracing chỉ riêng fixture PID, ghi denied operation/path/service tối thiểu; R4 existing log chưa đủ cho exact denial.
- Kiểm native policy preservation bằng fixture forced-admin/system requirements, load/refresh/restart; inaccessible/invalid requirements ngăn session admission, không quietly fallback. Không ghi hoặc đổi actual MDM.
- Với native scratch state không credential: kiểm SQLite+WAL/log/arg0/rollout paths, symlink/path escape và immutable launch revision; allowlist chỉ exact dependency đã đo.
- Khi runtime path đã chuẩn bị: separate canary secrets ở dummy file/env/FD/preferences; actual native shell/exec, file tool, hook, MCP process, native subagent, formatter/LSP pathway thử read và direct mutation/network. Mỗi positive/negative kết quả gắn exact version/hash/effective config; auth-privileged domain phải dùng canary resources, không secret thật.
- Chỉ sau credential-free boundary pass mới admission same-account supported auth session riêng: no refresh token copied vào worker, no API key route switch, output/log/trace redaction; cancellation/restart/policy changes phải giữ boundary. Token transport/refresh/source ownership là prerequisite thật nếu external-auth seam được chọn; docs/schema không hoàn thành nó.

Research này cung cấp diagnosis call site, source-supported mechanisms và concrete probe contract. **Không xác nhận profile/account data admission, startup authenticated session, exact denied syscall, privilege separation, provider parity hoặc final architecture.**
