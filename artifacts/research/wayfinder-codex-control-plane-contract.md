# Codex policy and local execution contract — Wayfinder #27

Status: source research complete; runtime binding/admission remains unverified. Scope: research against public source tag `rust-v0.160.1` and installed ACP `2.2.2`. This document selects no production architecture and changes no account, managed policy or provider. The native app-server bootstrap incompatibility from #26 and the independent executor subset from #18 remain distinct evidence.

## Result

Selecting a remote default executor does not, by itself, confine every execution path in the installed stock route. There are concrete local launch/read paths and configuration boundaries that need separate admission and operating-system enforcement. The inspected source supports conditional routing for ordinary process/filesystem tools; it does not establish a universal sandbox bridge or permit the conclusion that the privileged policy/auth process can safely execute arbitrary hooks/MCP commands.

The policy machinery has a meaningful fail-closed network contract: local policy is loaded before cloud configuration, errors make policy unavailable, and revision-bound permits can be revoked. That contract applies to participating application network transports. It neither redirects local command launchers nor enforces the worker's filesystem/process boundary.

Detailed tool inventory, supported gates and bounded negative findings are in `artifacts/research/wayfinder-codex-local-authority.md`. Both findings documents are evidence for the canonical resolution in GitHub issue #27; the map remains an index.

## Policy provenance, precedence and freshness

1. `load_local_application_requirements` reads the system requirements source and, on macOS, requires successful CFPreferences synchronization before reading the forced managed requirements key. It retains source layers. Application composition inserts cloud layers between system and MDM layers. Ordinary requirements also include legacy managed configuration; composition is field-specific, so an implementation must preserve the actual stack rather than flatten it to an unsourced boolean. [Application loader](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/config/src/loader/application.rs#L17), [ordinary managed requirements](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/config/src/loader/managed_requirements.rs#L69), [composition](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/config/src/requirements_layers/stack.rs#L153).
2. The reader accepts administrator values only when CF reports the key as forced; CF synchronization returning zero is an error. A denied forced-metadata call can report false, so success of ordinary config loading is not proof that managed policy was observed or absent. Earlier metadata helpers measured that ambiguity; this session did not read actual preference payloads or instruction-trace the native call sequence. [macOS reader](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/config/src/loader/macos.rs#L136), [earlier diagnosis](https://github.com/Riso-application-factory/zed-ai-crew/issues/26#issuecomment-6120441288).
3. ConfigManager serializes refreshes, publishes local policy before cloud loading, and checks both revision and snapshot identity when completing configuration. Local/cloud/parse failure marks policy unavailable and revokes retained permits. The policy controller starts unavailable, not permissive. A stale load cannot publish into a changed account/config generation. [Application refresh](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/app-server/src/application_network.rs#L32), [config construction](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/app-server/src/config_manager.rs#L429), [controller](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/http-client/src/network_policy.rs#L119).
4. Existing-thread turn entry calls `check_thread_model_provider`, which refreshes application requirements and rejects changed required provider selection/definitions. Explicit configuration/account reloads also load policy. No continuous MDM watcher or guarantee of instantaneous detection of every policy change was found in these reviewed call chains. Transport revocation begins when the controller is invalidated or a refreshed policy removes authorization; its existence is not a measured end-to-end revocation latency. [Turn entry](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/app-server/src/request_processors/turn_processor.rs#L530), [retained thread check](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/app-server/src/config_manager.rs#L262).
5. AuthManager invalidates its attached network policy when cached authentication changes owner. App-server binds auth and application clients to live controllers, with a narrower local bootstrap factory for cloud discovery. This is a source contract, not evidence that every external client or raw subprocess participates. [Auth invalidation](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/login/src/auth/manager.rs#L2629), [factory binding](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/app-server/src/config_manager.rs#L515).

`application.network` restricts exact normalized hosts to HTTPS/WSS. It does not express HTTP operation/resource gates, pathname restrictions, subprocess authority or worker account identity. Its checks occur before transport work; WebSocket connections retain permits and check revocation while reading/writing. Consequently a loopback `ws://` executor URL, while supported in general, is not automatically permitted under a restricted application policy. No insecure transport exception or enterprise setting change was selected. [Requirements schema](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/config/src/application_requirements.rs#L18), [destination checks](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/http-client/src/network_policy.rs#L26), [WebSocket permits](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/websocket-client/src/lib.rs#L165).

## Executor intent is a separate contract

Process requests can carry filesystem sandbox intent, an executor-local environment policy and managed-network launch/decision context. Filesystem requests carry sandbox intent separately. Those values are request data, not an independent proof of source provenance or a universally enforced parent policy. The outer executor profile is still necessary, especially when requests or MCP launchers omit optional sandbox fields. Remote unified-exec rejects unsupported capabilities rather than transparently running the command locally in the reviewed path. [Request construction](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/core/src/unified_exec/process_manager.rs#L222), [remote network preparation](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/core/src/tools/runtimes/unified_exec.rs#L360), [executor protocol](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/exec-server-protocol/src/protocol.rs#L305).

The selected environment's executor credentials are intentionally separate from the current model account. Application transport permits protect its connections; they are not a reason to copy provider credentials or the Human's PAT into worker environment/FDs. The earlier strict executor replay verified clean independent launch and inherited outer OS restrictions on synthetic child canaries. It did not verify native ACP propagation, fresh MDM observation, cancellation or every local handler. [Environment wiring](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/app-server/src/lib.rs#L614), [actual executor evidence](https://github.com/Riso-application-factory/zed-ai-crew/issues/18#issuecomment-6121682697).

## Why configuration alone is not a completed boundary

- Installed ACP creates requested stdio MCP config from command, args and env without an explicit `environment_id`. Codex defaults that server to local. Existing managed MCP matchers constrain name/command/args or URL but do not establish environment ownership, env or cwd. A remote thread default therefore does not force its MCP server into the executor. A guarded client must reject unowned additions and validate effective server ownership; those guards have not been implemented. [Default MCP environment](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/config/src/mcp_types.rs#L550), [MCP requirement matcher](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/config/src/mcp_requirements.rs#L52). Installed bundle lines and hash are recorded in the tool inventory.
- The canonical hook feature key is `features.hooks`, not `features.codex_hooks`. Disabling ordinary hooks does not automatically remove independent legacy notify or MCP-backed built-in cleanup handlers. A managed feature requirement may forbid disabling a feature. Mandatory hooks, servers and other administrator requirements must be honored or make the affected route unavailable; this research does not silently remove them. [Feature key](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/features/src/lib.rs#L1225), [hook registry](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/hooks/src/registry.rs#L119).
- Global ordinary-hooks disable filters handlers to built-ins and clears required-load errors in the reviewed engine. Merely observing a managed hook source is therefore not proof that the global feature is forced true. Admission must inspect the actual requirement state and retain mandatory authority; it cannot use this disable path to erase that authority. No actual administrator values were inspected. [Engine construction](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/hooks/src/engine/mod.rs#L239).
- Code-mode host launch, dedicated memory tools and browser/plugin paths need their own routing/gates. A remote executor default is not a guard for ambient environment inheritance or every local file reader. The detailed inventory distinguishes local commands, local reads, callbacks and provider-hosted tools rather than attributing all of them to one process tree.

CLI/session overrides and configuration files are inputs to inspect, not an OS security boundary. Request overrides are merged after base CLI overrides in ConfigManager; a proposed launcher must enforce its admitted configuration at every mutation/reload entry, including future subagents and plugin/MCP refresh. Source ownership matching is narrower than such an admission gate. [Override merge](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/app-server/src/config_manager.rs#L447).

## Options and return criteria

| Candidate | Contribution | Evidence required before admission |
| --- | --- | --- |
| Guarded stock launch plus independently confined executor | Reuses stock routing for ordinary tools. Proposed first bounded investigation, not chosen architecture. | Effective config rejects or explicitly confines all remaining local paths; immutable transport/server ownership; clean env/FDs; no mandatory-policy override; native policy startup and actual ACP dispatch/revoke controls. An engine process-exec allowlist may be investigated, but has not been tested here and is not assumed sufficient for local file readers. |
| Custom embedding/policy bridge | The Rust API accepts LoaderOverrides, EnvironmentManager and shared EmbeddedNetworkPolicy. | A real supported freshness/provenance/revocation bridge and isolated execution across all handlers. Embedded startup still calls ConfigManager policy loading; supplying an initial config does not bypass that obligation safely. Additional integration and pin maintenance are trade-offs, not an accepted decision. |
| Stronger isolation around the entire native engine | Can constrain local handlers that stock routing misses. | Native auth/MDM/bootstrap compatibility, credential mediation and actual macOS/runtime constraints. Prior nested different-policy Seatbelt failed. No VM, account switch or alternate architecture is selected merely by naming this option. |

Embedding evidence: [API inputs](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/app-server/src/in_process.rs#L137), [policy/bootstrap](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/app-server/src/in_process_bootstrap.rs#L20). Prior nesting evidence: [controlled contrasts](https://github.com/Riso-application-factory/zed-ai-crew/issues/18#issuecomment-6111928834).

The research conclusion is a counterexample to admitting the current default-remote candidate, not proof that every guarded stock configuration is impossible. Return to Confinement with a bounded probe plan: first validate the effective configuration/launcher admission against hostile synthetic MCP/notify/plugin/memory/code-mode additions and mandatory-feature constraints; keep policy failure closed. Next, when a policy-preserving launch candidate is established, use actual pinned ACP with an owned independently confined executor and controlled synthetic backend to show public read/command/patch results, outside denial, native result propagation and absence of local fallback. Deliberately losing the executor/policy must fail, not silently select local. Actual app-server startup remains unresolved; do not swap in a fake initialized server or relax preference IPC and call that native binding.

Research closes its source question; these proposed checks are work for #18. Authenticated/private-profile, Antigravity, host FS/terminal/formatter/LSP/build, cancellation and whole-product quality remain open. No new Human login or product-prioritization decision is inferred from the source findings.

## Verification limits

This session read source and inspected installed program text. No native tool, model, authentication, provider call or managed value was executed/read. Source tests are evidence of intended invariants only; they were not run. A hash manifest and exact published-body readback will accompany the canonical resolution. Runtime claims refer explicitly to earlier #18/#26 artifacts, not new tests in this research session.

The source tag/archive and installed binary version are separately identified. Matching version strings is not binary-to-source attestation; the installed ACP bundle has its own byte fingerprint, and earlier native runs retain their executable hash. The conclusion here is source-supported, not a new exploit demonstration.
