# Codex pinned executor seam — decision evidence for Confinement

Status: source-verified research, runtime binding not established by this document. Owner: research agent for the Coordinator. Scope: installed Codex CLI `0.160.1` and Codex ACP `2.2.2`; public source and installed program text only. No authentication, account change, model turn, real credential/configuration value read, production change or tracker mutation was performed by this research agent.

## Finding

The pin contains a real configurable process/filesystem executor seam. It is broader than an approval callback: app-server can select a separately running exec-server, and the selected non-local environment supplies both a process backend and `ExecutorFileSystem`. This supports a candidate control-plane/execution split. It does **not** establish that every model-reachable path moves out of app-server, that administrator policy remains fresh under denied preference access, or that the installed ACP adapter successfully binds to it.

The standalone CLI command is explicitly experimental. Its configuration startup differs from app-server: `--strict-config` does not make the two startup policy paths equivalent. A successful executor handshake therefore must not resolve the existing app-server bootstrap failure or admit a worker configuration by itself.

## Sources and binding

All Codex links below refer to tag `rust-v0.160.1`, downloaded as the [public source archive](https://github.com/openai/codex/archive/refs/tags/rust-v0.160.1.tar.gz), SHA-256 `5226394058e04c5404fe737b84fbede38ebf41d88a72eb8b27f3d1c6ea23373b`. A tag and archive hash identify the reviewed bytes; neither attests to a installed binary build. The root probe separately identifies the actual executable.

1. App-server constructs `EnvironmentManager` after configuration/auth bootstrap and passes the effective application HTTP policy to it. Normal startup uses the Codex-home provider; the `ignore_user_config` path uses environment variables instead. Changing that ignore flag is not proposed. [app-server startup](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/app-server/src/lib.rs#L614).
2. The Codex-home provider reads `environments.toml`. Entries select exactly one WebSocket URL or stdio program, with optional arguments, additive environment variables and cwd. The file controls `default` and `include_local`; malformed/unknown fields and invalid defaults fail. A configured non-local entry is represented by a remote environment even when its executable runs on the same Mac. [TOML provider](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/exec-server/src/environment_toml.rs#L27), [manager construction](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/exec-server/src/environment.rs#L300).
3. If that file is absent, `CODEX_EXEC_SERVER_URL` selects the remote default and excludes the local environment. Unset/empty selects local; `none` disables environments. This is an existing stock configuration route, without changing `HOME` or `CODEX_HOME`. Noise-registration variables have precedence and must not be silently inherited into a synthetic test. [default provider](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/exec-server/src/environment_provider.rs#L57), [precedence](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/exec-server/src/environment.rs#L183).
4. Direct WebSocket supports opt-in capability/signed-token authentication; authenticated URL entries require TLS or loopback. Authentication occurs when connecting; stored tokens are reused on reconnect without automatic refresh. Stdio has no listener authentication; ownership comes from its process/pipe boundary. Source CLI accepts `--listen stdio` / `stdio://` in addition to WebSocket, although the reviewed README transport list omits stdio. Remote registration is another route, with external identity/registry dependencies; it is unnecessary for the smallest local proof. [CLI transport](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/cli/src/exec_server_command.rs#L66), [authentication contract](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/exec-server/README.md#L29).
5. App-server `thread/start.environments` is experimental; omission selects the default when environment access is enabled. Installed ACP `newSession` calls `threadStart` with `config`, provider, cwd and optional developer instructions, without forwarding `environments`. Consequently default process-level selection is the candidate stock binding; explicit per-session selection is not source-supported by this adapter call. `CODEX_CONFIG` merges session config, but is not evidence of per-session environment forwarding. [thread contract](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/app-server-protocol/src/protocol/v2/thread.rs#L136). Installed bundle `dist/index.js` lines `35330–35341`, `35437–35461`, SHA-256 `6b1bb4e7e9caaf4aeca1042ae4aec2dc2433b0b0e4b1614b38a4d41699902aaa`; this claim was checked against the installed file, not an unverified upstream adapter tag.

## Policy startup distinction

App-server `ConfigManager.load_with_cli_overrides` first refreshes application network policy. Its loader synchronizes macOS preferences before reading forced application requirements; failure makes policy unavailable. It then builds ordinary config layers. Standalone local `exec-server` directly calls `ConfigBuilder`; ordinary managed layers read forced preferences, without calling the application-requirements refresh path. `has_local_managed_configuration` has a caller in TUI startup, not the reviewed app-server startup; attributing app-server failure to that detector specifically would be unsupported.

In the standalone command's non-strict branch a failed config load is converted to `None`, with a default HTTP factory. The strict branch propagates that load failure, but its success still does not prove successful fresh MDM policy observation. Denied forced-metadata access can report false; neither startup success nor the `strict-config` flag establishes policy absence. A future split must retain provenance, precedence, freshness/revocation and fail-closed behavior, rather than moving these obligations to an unvalidated empty snapshot.

## Smallest safe synthetic checks

First exercise the installed executable's strict stdio executor directly under the existing outer executor policy, without app-server, model, account or broad preference grants. Protocol is JSONL in the Codex dialect (no `jsonrpc` field): send `initialize` with `clientName`, receive a session and executor metadata, then notify `initialized`. Read an existing synthetic public file through `fs/readFile`; request existing outside and symlink canaries and require denial. `process/start` uses logical `processId`, argv, `file://` cwd, env and tty; collect `process/read` with advancing `afterSeq` until exited/closed, checking base64 chunks and errors. Run public command and boundary canaries with positive unconfined controls. Do not confuse a zero driver exit with a passed native assertion. [wire contract](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/exec-server-protocol/src/rpc.rs#L1), [requests](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/exec-server-protocol/src/protocol.rs#L305).

Then a separate binding proof must show actual installed ACP selects that executor, receives the expected result, and does not execute locally. Existing strict app-server bootstrap remains a blocker for this second check. Success of the first check may establish an executor component without fresh MDM semantics; it cannot clear that blocker. Choosing a custom embedding or relaxing control-plane privileges is a separate unresolved architecture decision, not a conclusion of this report.
