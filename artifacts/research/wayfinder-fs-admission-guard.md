## Minimum effect seams

**Established source facts.** `ApplyPatchRuntime::run` is after the orchestrator's approval/sandbox work and receives `ToolCtx` (named `_ctx` in the baseline). It selects the turn filesystem and sandbox before invoking `apply_patch_with_options`. This gives a specific after-approval source recheck point while retaining the native environment, permission and delta paths. It is a runtime recheck rather than a receiver lease. [Runtime](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/core/src/tools/runtimes/apply_patch.rs#L155-L207), [handler/orchestrator](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/core/src/tools/handlers/apply_patch.rs#L522-L608).

`RemoteFileSystem` mutators await lazy client acquisition then send individual RPCs. `ExecServerClient::call` further awaits recovery/readiness through `rpc_client()` before calling that exact RPC client. These generic calls do not loop over a completed sent filesystem mutation; source does not support a claim of transparent successful mutation replay. Existing #32 process-only issuance uses its actual initialized receiver target; FS methods do not share its admission envelope. [Remote write/create](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/exec-server/src/remote_file_system.rs#L112-L153), [remove/copy](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/exec-server/src/remote_file_system.rs#L264-L306), [call/recovery](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/exec-server/src/client.rs); current #32 `client.rs:759–762,967–1034,1299–1320` separately fingerprinted.

The receiver registry deserializes `WireFsWriteFileParams`, `WireFsCreateDirectoryParams`, `WireFsRemoveParams` and `WireFsCopyParams`, then resolves wire sandbox intent into native typed params before forwarding. Handler initialization includes attachment checks, but its FS routes have no current per-operation admission in #32. `FileSystemHandler` decodes base64 for write, supplies option defaults and awaits the selected `LocalFileSystem` operation. [Registry](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/exec-server/src/server/registry.rs#L158-L208), [wire conversion macro](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/exec-server-protocol/src/protocol.rs#L839-L875), [write/create handler](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/exec-server/src/server/file_system_handler.rs#L183-L222), [remove/copy handler](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/exec-server/src/server/file_system_handler.rs#L298-L335); #32 handler initialization/attachment is at `handler.rs:437–465` in the fingerprinted snapshot.

**Proposed bounded interface.** Obtain the actual initialized RPC target after readiness, request a distinct filesystem grant for one typed normalized operation, serialize the existing `WireFs*` request and add its explicit envelope. Receiver first parses that wire type and resolves the same typed sandbox intent, then validates the grant against the actual receiver attachment and normalized operation. Do not hash a raw caller JSON object on one side and the typed request on the other: option defaults, omitted `followSymlinks`, explicit nulls and legacy sandbox `policyCwd` resolution can differ. This is a comparison/compatibility concern, not an observed exploit. An exact typed-request hash binds base64 text, not canonical decoded bytes; document the chosen contract rather than claim equivalent encodings necessarily match.

Keep separate operation/content/path/attempt identity, thread and owner-admitted context, selected executor, exact receiver session/connection and current revision. For `fs/copy`, hashing the typed request binds source/destination/options/sandbox, not the source bytes or inode read later by the native copy. A source file can change independently of the owner publication guard. Immutable-source-content admission needs additional content/identity validation; the bounded path/operation grant must not be described as already proving it. Arbitrary extra fields, prompts, telemetry and generation labels do not issue authority. A public synthetic issuer can demonstrate this interface, but cannot certify actual MDM/account/role/skill/provenance ownership.

Acquire the receiver owner guard immediately before the awaited native FS operation, retain it until that operation has settled, then report completion/error. This protects one operation, including its helper work, rather than an entire patch batch. Publication takes the corresponding exclusive owner guard and may wait for an already admitted effect; distinguish revocation of future admission from cancellation/rollback of admitted work. Recheck attachment when acquiring the guard and before entering an effect if the prototype deliberately waits there. A held policy guard alone does not prevent attachment from changing unless attachment publication participates in the same contract.

## Filesystem helpers and lifetime risks

`LocalFileSystem` selects sandboxed versus direct writes from the explicit filesystem context and validates host path compatibility. Preserve this selection. Sandboxed operations call `FileSystemSandboxRunner`, build the sandbox command, spawn the native helper, write its stdin, wait for output and decode the native response. Helper invocation is `runtime_paths.codex_self_exe --codex-run-as-fs-helper`; `arg0_dispatch_or_else` handles this flag before normal app-server startup. The #32 app-server main still calls that dispatch routine, so it can be a valid helper executable when runtime paths point at it. No helper executable compatibility or runtime evidence was executed by this audit. [FS selection](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/exec-server/src/local_file_system.rs#L95-L126), [sandboxed FS runner](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/exec-server/src/sandboxed_file_system.rs#L99-L113), [helper command construction](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/exec-server/src/fs_sandbox.rs#L150-L200), [helper IO/wait](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/exec-server/src/fs_sandbox.rs#L392-L434), [arg0 dispatch](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/arg0/src/lib.rs#L104-L114); prototype main is fingerprinted below.

The helper directly uses `Command::spawn`, outside the process-start admission path. That command clears environment and defaults to `kill_on_drop(true)`/`KillAndReap`, not an unrestricted detached process. Helper launcher also uses explicit macOS descriptor policy and `SpawnFallback::ReturnError`. Nevertheless, a guard dropped with a cancelled RPC future does not by itself establish that helper kill/reap or all preceding effects have completed before publication. [Child defaults](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/utils/pty/src/child_command.rs#L94-L115), [helper spawn](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/exec-server/src/fs_sandbox.rs#L519-L551), [owned child wait](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/utils/pty/src/child.rs#L51-L94).

Receiver dispatcher races each awaited route against disconnection and aborts task routes on shutdown. Direct filesystem writes use Tokio filesystem futures, while recursive direct copy is performed inside `tokio::task::spawn_blocking`. Dropping the outer await can therefore relinquish an ordinary route-scoped guard before the independently scheduled blocking operation settles. **Inference:** a cancellation-safe admission contract needs an effect-owned guard lifetime (for example, a supervised owned operation task that retains its guard through completion even if its RPC waiter disappears), or a precisely bounded unsupported cancellation case. It must state whether already acquired effects may finish after client cancellation, not claim rollback. [Disconnect handling/shutdown](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/exec-server/src/server/request_dispatcher.rs#L235-L320), [direct write](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/exec-server/src/local_file_system.rs#L654-L668), [blocking recursive copy](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/exec-server/src/local_file_system.rs#L927-L970).

An owner-controlled spawned task retaining a guard is a proposed design, not proof of authority-safe cancellation. It also requires explicit task-error observation and cleanup/lifetime controls. Receiver/whole-process termination can still kill a helper or stop the task without application-level completed receipts; committed effects remain a separate filesystem fact.

## Error, retry and partial-delta constraints

Receiver FS mapping preserves NotFound as `-32004`, InvalidInput/PermissionDenied as `-32600`, and other errors as internal errors. Remote mapping retains the server message, classifies `-32004` as `io::ErrorKind::NotFound`, `-32600` as `InvalidInput`, and other server errors as `Other`. Admission denial should not masquerade as NotFound or a transport BrokenPipe: native patch interprets NotFound as missing-parent recovery and sends `createDirectory`, then retries `writeFile`; each is a new mutation requiring distinct admission. [Receiver error mapping](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/exec-server/src/server/file_system_handler.rs#L347-L355), [remote mapping](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/exec-server/src/remote_file_system.rs#L410-L427), [missing-parent recovery](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/apply-patch/src/lib.rs#L799-L857).

The patch layer wraps IO failures with path/context and returns an accumulated `AppliedPatchDelta`. Its write-error macro marks delta inexact conservatively, including an admission failure that was actually before write. Do not reinterpret native inexactness as observed write leakage, or a failed ACP tool update as evidence of zero filesystem effects. Move writes destination, records an Add delta, then removes source and updates delta; later deny leaves earlier allowed destination content. A whole-patch transaction/rollback is absent. [Delta/failure](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/apply-patch/src/lib.rs#L423-L454), [write macro](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/apply-patch/src/lib.rs#L488-L501), [Move order](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/apply-patch/src/lib.rs#L614-L707), [event partial delta](https://github.com/openai/codex/blob/rust-v0.160.1/codex-rs/core/src/tools/events.rs#L418-L440).

A fresh grant for each readiness-acquired attempt is compatible with denying replay. If a transport dies after the effect but before its response, failure does not prove no effect and the next retry must not reuse the consumed token or assume rollback. Native generic FS call source gives one send after readiness, so probe an explicit retry/resume as a distinct attempt and retain on-disk observations.

## Proposed verification frontier

These checks are recommendations, not research executions:

1. Unchanged ACP custom patch stable approval succeeds; policy mutation during the actual permission wait now fails before mutation; restoring valid policy succeeds with visible native error on the deny.
2. Raw native receiver operation positives for write/create/remove/copy, then missing/forged/stale/revoked/replayed and mismatched operation/content/path/session/connection grants with exact content/non-effect observations.
3. Clearly labelled deterministic receiver waits on each side of guard acquisition: replacement before acquisition rejects; publication during the acquired operation waits and succeeds only after admitted completion. Different cases must state which timing was actually observed.
4. Native missing-parent retry sequence, multi-hunk prefix and Move destination-written/source-remove-denied observations; report directory creation and all retained deltas explicitly.
5. Actual resume/retry, old attachment rejection and cancellation/disconnect while mutation is delayed. Distinguish pre-admission cancellation, already admitted operation completion and any unresolved blocking/helper lifetime.
6. Preserve outside worktree/traversal/symlink/Git metadata denial and exercise actual sandbox helper executable/response; no unsupported host-authority fallback to obtain positive controls.

Generic MCP preparation/live calls, child-agent identity, unrestricted host paths and complete three-provider provenance remain Confinement #18. This source audit does not close #33.
