## Kết luận từ source

1. `run_tests` nhận `pull_request`, `merge_group` và push vào main/release branch, nhưng cả `orchestrate`, `check_style` và `tests_pass` đều giới hạn owner thành `zed-industries` hoặc `zed-extensions`. Fork `Riso-application-factory` không qua các guard này. Các job macOS phụ thuộc hai job đầu; `run_tests_mac` còn loại `merge_group`. Bật Actions không tự làm đường này chạy. Sources: [.github/workflows/run_tests.yml](../../.github/workflows/run_tests.yml), lines 8–22, 142–144, 441–446, 1007–1031.
2. Runner labels có cấu hình Namespace Linux/macOS và Windows self-hosted; chúng không phải bằng chứng fork đã có quyền dùng hoặc capacity. Sources: [runners.rs](../../tooling/xtask/src/tasks/workflows/runners.rs), lines 3–18; workflow lines 22, 144, 446. Runner availability thuộc audit API của Coordinator.
3. `tests_pass` chấp nhận cả `skipped` lẫn `success`; aggregate này không đủ làm evidence thực thi mandatory checks. Job `check_postgres_and_protobuf_migrations` có thật nhưng vắng trong `tests_pass.needs`, các lời gọi `check_result` và env tương ứng. Sources: workflow lines 946–991, 1007–1087, đặc biệt line 1040. Nếu phạm vi thay đổi làm protobuf compatibility bắt buộc, aggregate xanh không chứng minh nó pass.
4. macOS nextest chạy `--workspace --no-fail-fast --no-tests=warn` với optional reverse-dependency filter; không truyền `--all-features` hay `e2e`. Không có tests được chọn có thể chỉ là warning ở đường cấu hình này. Sources: workflow lines 484–485; [steps.rs](../../tooling/xtask/src/tasks/workflows/steps.rs), lines 23–44.
5. Common provider E2E tests mang `ignore` khi không bật `e2e`. Sole invocation ở baseline nằm trong **native Zed agent**, authenticate Anthropic và chọn `claude-sonnet-4-latest`. Nó không phải matrix Claude ACP/Codex ACP/Antigravity ACP. Sources: [e2e_tests.rs](../../crates/agent_servers/src/e2e_tests.rs), lines 333–381; [native_agent_server.rs](../../crates/agent/src/native_agent_server.rs), lines 61–101. `git grep -n 'common_e2e_tests!' <baseline> -- crates` trả một invocation ở line 67. Test helpers còn tạo production HTTP client và thực sự gửi prompt/connect/new session: e2e_tests.rs lines 20–32, 385–429. Không tự chạy những tests này trong research.
6. GPUI test support, renderer benchmarks, Zed visual runner và live-provider E2E là những bề mặt khác nhau. Generic Rust tests không chứng minh screenshot, Human trải nghiệm UI, targets W1/W3 hoặc tất cả adapters. Sources và commands bên dưới.

## Environment and selection facts

- Toolchain pinned Rust1.98.1 with rustfmt/clippy/rust-src and target list: [rust-toolchain.toml](../../rust-toolchain.toml), lines 1–9. macOS source docs require rustup, Xcode/macOS components/CLI selection and cmake: macos.md lines 12–37. Metal errors on macOS26 have documented tooling remedies, lines 145–156. **This audit did not check installation or license/permission state.**
- CI installs Node24 and nextest, uses Namespace Rust cache and custom labels: workflow lines 441–483. A local macOS path need not have Namespace capacity or upstream R2 credentials. R2 cache setup explicitly returns when R2_ACCOUNT_ID absent: [setup-sccache](../../script/setup-sccache), lines 76–80; absence of cache credentials is not by itself a mandatory build impossibility. Download/runtime prerequisites still need preflight.
- Local Cargo config sets tokio_unstable and deployment target; CI additionally merges parent `.cargo` settings with `-D warnings` and debug limited. [.cargo/config.toml](../../.cargo/config.toml), lines 1–3, 23–24; [.cargo/ci-config.toml](../../.cargo/ci-config.toml), lines 1–16. Local/CI parity claims need effective config/rustflags/features captured, not just command label.
- Changed package selection is derived by cargo metadata, maps actual crates/tooling package directories, adds settings/assets for asset changes, falls back to all packages on toolchain/root Cargo/workflow config changes or no mapped packages, and otherwise uses union of `rdeps(...)`. Workflow lines 55–112. Test applicability is separate path regex, lines 115–118. Neither package impact nor feature selection should be guessed from a check name.
- nextest config default timeout60s; DB group serialized, specific slow tests get300s. nextest.toml lines 1–48. A pass does not establish the product's zero ≥1s UI-stall target; these are test-runner deadlines with a different purpose.
