# Wayfinder · Ranh giới worker và thẩm quyền mutation

**Ngày nghiên cứu:** 2026-10-11. **Ticket canonical:** [Xác định cơ chế cưỡng chế ranh giới worker và thao tác Crew](https://github.com/Riso-application-factory/zed-ai-crew/issues/6). **Trạng thái:** research có kết luận; enforcement chưa kiểm chứng; lựa chọn danh tính riêng đã được Human xác nhận ở [resolution](https://github.com/Riso-application-factory/zed-ai-crew/issues/16#issuecomment-6107655323). Báo cáo này là evidence; quyết định nằm trong ticket canonical.

## Kết luận

Giữ PAT rộng của Human như đã chốt. Phạm vi quyền token và việc worker có thể dùng token là hai điều khác nhau. Worker đọc được PAT và đi trực tiếp tới GitHub thì Crew gateway không còn là bên duy nhất kiểm soát mutation. Lời nhắc, cwd, ACP permission và hostname allowlist không chứng minh được ranh giới đó. Cần kiểm soát từ lúc khởi chạy worker, đường gọi qua Zed và đường side effect qua gateway. Đây là yêu cầu kỹ thuật suy ra từ boundary đã chọn, chưa phải mechanism được Human xác nhận hoặc chạy thành công.

Một blocker nghiệp vụ đã xác định được: GitHub không cho tác giả PR approve PR của chính mình. Nếu Crew mở PR bằng PAT của tài khoản Human thì Human là tác giả; luồng D17 yêu cầu Human `APPROVED` review không thực hiện được. Đây là suy luận có điều kiện từ API identity, **không phải quan sát PR runtime của Crew**. [GitHub: approving a pull request](https://docs.github.com/en/pull-requests/how-tos/review-pull-requests/approving-a-pull-request-with-required-reviews).

Nếu PAT vẫn đọc được bên trong worker, ít nhất phải chặn mọi đường trực tiếp dùng nó cho GitHub và mọi đường rò rỉ sang nơi khác. Đây là trade-off kiến trúc đề xuất, không đổi scope PAT hay tuyên bố Human đã chấp thuận cấu hình isolation.

## GitHub approval và những gì gateway có thể chứng minh

Reviews API trả reviewer, `state`, `submitted_at`, `commit_id`; code cần phân trang và diễn giải các review mới/dismissed thay vì lấy approval đầu tiên. [GitHub reviews API](https://docs.github.com/en/rest/pulls/reviews#list-reviews-for-a-pull-request).

Merge API hỗ trợ expected head `sha`; synchronous endpoint trả 409 khi lệch. Docs hiện có asynchronous merge API với expected head và trạng thái pending/enqueued/merged; accepted hoặc enqueued chưa phải OUTPUT merged. Head guard không atomically pin review state, checks hoặc base SHA trong contract được dẫn, nên không được gọi nó là transaction cho toàn approval policy. [GitHub pull requests API](https://docs.github.com/en/rest/pulls/pulls#merge-a-pull-request).

Branch protection có stale-review dismissal/required reviews/checks và bypass controls; admin có thể được miễn theo cấu hình. Không có snapshot policy mới ở nghiên cứu này. Gateway có thể cưỡng chế đường thao tác Crew quản lý; nó không ngăn Human hoặc actor khác có cùng quyền gọi GitHub trực tiếp. Để tuyên bố server cũng ngăn merge thiếu approval phải inspect policy/bypass/permissions thực tế và validation riêng, không tự thay policy. [GitHub protected branches](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches).

**Human decision đã xác nhận:** [Chọn danh tính tạo PR để Human có thể approve — resolution](https://github.com/Riso-application-factory/zed-ai-crew/issues/16#issuecomment-6107655323). Human chọn danh tính Crew riêng tạo PR, Human review bằng tài khoản riêng và giữ PAT rộng. Chưa chọn GitHub App hay tài khoản bot, chưa provisioned; phần kỹ thuật được nghiên cứu ở [Xác định cơ chế GitHub identity riêng cho Crew](https://github.com/Riso-application-factory/zed-ai-crew/issues/21). Identity riêng cũng chưa chứng minh người/model không thể giả approval: trusted gateway phải cấm review-create/submit bằng Human credential; kiểm intent review chỉ từ GitHub actual review của Human. [Quy tắc không self-approve](https://docs.github.com/en/pull-requests/how-tos/review-pull-requests/approving-a-pull-request-with-required-reviews).
