# Antigravity model producer admission: public SDK and ACP source research

Research date: 2026-10-14 (UTC+7). Canonical question: [research #52](https://github.com/Riso-application-factory/zed-ai-crew/issues/52). Status: source findings verified; installed ACP producer admission remains **investigate**. This note records source reads and downloaded public artifacts, not an executed runtime probe.

**Finding:** The pinned public Python SDK exposes model endpoint URLs, HTTP headers and API keys. Its startup WebSocket also carries a key, but that key authenticates the SDK-to-runtime control connection; it is not documented as native-to-model HTTP producer authentication. No inspected first-party source establishes a configurable model admission credential/header parser for the unchanged installed Antigravity ACP 1.3.0 adapter. A bounded compatibility probe can use the already measured `AGY_LLM_GATEWAY_URL` override to test a gateway-owned, per-epoch URL prefix, but prefix preservation, credential custody and the claimed threat scope remain unverified. Possession of such a prefix would be a bearer capability, not PID or native-incarnation attestation.

## Authentication, custody and scope

The existing [actual model sender report](../evidence/wayfinder/confinement/antigravity-model-sender-report.md) proves six unrelated-process requests forwarded across two runs while the registered adapter/native graph was correct; two poisoned-epoch requests were denied. Caller-declared JSON sessionId, URL metadata or a public correlation header cannot repair that sender binding. The report's actors were unconfined public local processes; the experiment is not a private-worker sandbox escape.

A supervisor-created fresh credential passed to the intended native transport could support a **possession** boundary only if its custody is enforceable against the named actors. The public SDK passes model configuration on the startup-controlled WebSocket rather than as native command arguments. However, its startup code merges ambient environment with provided variables, or inherits the ambient environment when none is supplied; the source does not promise a clean environment or credential exclusion from native child processes ([local_connection.py:1500–1519](https://github.com/google-antigravity/antigravity-sdk-python/blob/f61cb2fa54a0a3c46dac690f32e4346995662297/google/antigravity/connections/local/local_connection.py#L1500-L1519)). General endpoint/provider API keys do not become local producer credentials merely by naming them that way.

The inspected SDK supports closing the WebSocket, closing runtime stdin, waiting and escalating to process termination during connection cleanup ([local_connection.py:592–612](https://github.com/google-antigravity/antigravity-sdk-python/blob/f61cb2fa54a0a3c46dac690f32e4346995662297/google/antigravity/connections/local/local_connection.py#L592-L612)). This is source-described cleanup, not demonstrated revocation of already accepted model requests or a substitute for #51's actual graph quiescence and #50's immutable history. A gateway-owned capability would need its own epoch state, fail-closed owner-loss handling, pre-forward checks and retirement. Neither historical credentials nor repaired history may revive execution grants.

Separately enforcing endpoint reachability could establish that only the admitted graph can submit traffic, but this note does not research or claim an OS enforcement mechanism. Same-user unconfined actors must remain an explicit boundary question; worker-only denial does not establish host-wide sender exclusion. Process/socket observation remains diagnostic evidence, not an atomic production admission contract.

## Smallest alternatives and next bounded decision

1. **Unchanged ACP plus gateway-owned URL-prefix capability: investigate.** Use the already measured URL override without inventing a new ACP field. SDK base_url support is a source lead; exact ACP prefix preservation remains a compatibility hypothesis. An opaque prefix is neither documented vendor authentication nor native PID attestation. This is the smallest narrowly expressible transport/custody probe without switching the installed adapter.
2. **Public SDK/native endpoint HTTP headers: conditional investigation.** Precise fields exist, allowing a standalone raw-native or public SDK wire-compatibility probe. Such a positive would still leave the ACP configuration path unresolved. A replacement adapter/native interception architecture is not selected or authorized by this finding.
3. **Enforced reachability/isolation: independent specialist evidence needed.** It may supply the missing boundary, but requires actual exclusion and lifetime evidence over the intended producer, unrelated processes and admitted descendants. A random port, process enumeration or UID alone is insufficient evidence for an incarnation claim.

Proposed next prototype question: **Does unchanged ACP 1.3.0 preserve a fresh opaque prefix from its already measured gateway URL onto every native model request, and can the prefix remain unavailable to actors in the actual claimed threat scope across preparation, effects, retirement and recovery?** No such prototype ran during this research.

Observable planned controls:

- Legitimate native request reaches an exact receiver path, with admitted incarnation/epoch recorded before forwarding; optional capability changes are checked against #50 history projection and #51 graph fence positives.
- Actual separate same-user actors send matching, foreign and absent model session fields while using missing/foreign prefixes; receiver must observe zero upstream forwarding. Repeat against preparation and current endpoints.
- Deliberately supplying the current valid prefix is a possession positive. If accepted, record it as bearer semantics, not producer authentication. Attempts to obtain it through inherited environment/descriptors or accessible process arguments/state/logs are custody controls; inability to read one surface is not blanket exclusion.
- Retired-epoch prefix, repaired poisoned history and owner loss must deny before forwarding. Restored unchanged ACP with a fresh quiescent epoch must preserve genuine historical facts while rejecting retired capabilities and grants.
- If prefix stripping, routing incompatibility, credential exposure, unexpected producer access or incomplete reclaim occurs, return that exact observed limit and stop that admission claim. Do not repair the result by silently replacing ACP or excluding same-user actors.

Resolution is **investigate**, with a precise installed-path compatibility and custody question. Source research is complete within its bounded inventory; #18 confinement, private data admission and the overall destination map remain unresolved. No real authentication, inference, private target data, installed binary extraction/patch/replacement, profile/account/model/MDM/PAT/billing changes, vendor contact, production service, commit or PR were performed.
