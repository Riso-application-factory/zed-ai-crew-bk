# Wayfinder · GitHub identity riêng cho Crew

**Ngày:** 2026-10-11. **Canonical research:** [Xác định cơ chế GitHub identity riêng cho Crew](https://github.com/Riso-application-factory/zed-ai-crew/issues/21). **Kết quả:** khuyến nghị kỹ thuật có nguồn; chưa provisioning hoặc kiểm runtime.

Human đã trả lời `ok` cho **Crew tạo PR bằng identity riêng, Human review bằng tài khoản Human**; giữ PAT rộng. [Resolution xác nhận](https://github.com/Riso-application-factory/zed-ai-crew/issues/16#issuecomment-6107655323). Câu trả lời này chưa chọn App hay bot, chưa cấp quyền tạo App/account/key. App token là credential riêng cho identity Crew đã chấp nhận; không yêu cầu thay thế, thu hồi hoặc giảm quyền PAT Human. Đã đọc [glossary](../../GLOSSARY.md), [ADR-0001](../../docs/adr/0001-hybrid-orchestration.md), [solution-scope](../shaping/solution-scope.md) và [authority research](wayfinder-authority.md); không sửa các tài liệu đó.

## Khuyến nghị

**Đề xuất GitHub App installation identity, token chỉ nằm trong trusted Crew gateway.** Có thể dùng recommendation trong kiến trúc đề xuất và thiết kế fixture ngay; đây không phải một approval gate mới. Cơ chế này phù hợp automation lâu dài, identity tách Human, quyền theo installation/repository và token ngắn hạn. Worker gửi proposal; code kiểm operation rồi gateway thực hiện Git/API. Human review bằng GitHub web; workflow thông thường không cần dùng PAT Human để tạo PR, push hoặc merge. PAT Human vẫn giữ nguyên scope; không coi việc bỏ nó khỏi worker là thay scope.

Bot account PAT là fallback nếu repository owner không cho cài App nhưng cho bot access, hoặc có capability thực tế App không đáp ứng. Chưa có evidence cho hai điều kiện đó. Không tạo fallback account hoặc thêm Human approval gate chỉ vì có hai phương án kỹ thuật.

## Capability và permission đề xuất

Bảng này kiểm các thao tác cốt lõi, không khẳng định đã kiểm mọi endpoint tương lai của Crew. Các endpoint dẫn liệt kê installation token và fine-grained PAT; PAT classic cần scope/API support tương ứng. Policy repo vẫn có thể chặn dù token có permission.

| Operation cần cho Crew | Permission App / fine-grained API | Evidence trực tiếp |
| --- | --- | --- |
| HTTP Git clone/fetch/push | `Contents`: read cho đọc, write cho ghi; HTTP Git dùng installation token. | [Installation HTTP Git](https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/authenticating-as-a-github-app-installation), [Write refs](https://docs.github.com/en/rest/git/refs#create-a-reference). |
| Tạo/sửa Issues | `Issues`: write. Native hierarchy/dependencies/issue types cần kiểm endpoint riêng khi contract backlog rõ. | [Issues API](https://docs.github.com/en/rest/issues/issues#create-an-issue). |
| Tạo/sửa PR | `Pull requests`: write; branch đã được push. | [PR API](https://docs.github.com/en/rest/pulls/pulls#create-a-pull-request). |
| Đọc review của Human | `Pull requests`: read, nằm trong grant write ở trên. Review API trả actor, state và commit. | [Reviews API](https://docs.github.com/en/rest/pulls/reviews#list-reviews-for-a-pull-request). |
| Merge PR | `Contents`: write; dùng expected head. Accepted/enqueued không đồng nghĩa merged. | [Merge API](https://docs.github.com/en/rest/pulls/pulls#merge-a-pull-request). |
| Đọc quality checks | `Checks`: read; `Commit statuses`: read khi repo dùng statuses. | [Checks API](https://docs.github.com/en/rest/checks/runs#list-check-runs-for-a-git-reference), [Statuses API](https://docs.github.com/en/rest/commits/statuses#get-the-combined-status-for-a-specific-reference). |
| Thay workflow files | Xem thêm `Workflows`: write khi thao tác ghi liên quan workflows; không tự cấp trong research. | [Refs API permission alternatives](https://docs.github.com/en/rest/git/refs#create-a-reference). |

**Grant ban đầu đề xuất:** Metadata read, Contents write, Issues write, Pull requests write; Checks/Commit statuses read theo bộ check dùng thực tế. Không đề xuất Administration, organization permissions hoặc bypass rules cho luồng này. Bộ grant thuộc App mới, không sửa PAT Human. Cần inspect permission/installation response thực tế trước dùng, không suy từ tên App.

Permission GitHub không biểu diễn đủ business rules Crew: `Pull requests: write` còn cho review-write endpoints; `Contents: write` không chỉ cho “merge đúng Story sau Human approval”. Gateway vẫn cần operation allowlist, repo/ref binding, check đúng version và reviewer identity cố định; không cho worker raw API hoặc credentials. [Reviews write endpoints](https://docs.github.com/en/rest/pulls/reviews#create-a-review-for-a-pull-request). Ranh giới này tiếp tục kiểm ở [confinement](https://github.com/Riso-application-factory/zed-ai-crew/issues/18) và [gateway](https://github.com/Riso-application-factory/zed-ai-crew/issues/19), không được research identity thay thế.

**Giới hạn bot fallback cần chú ý:** PAT overview nói fine-grained PAT chưa hỗ trợ outside/repository collaborators và Checks API; Checks endpoint lại liệt kê loại token này. Bot fallback cần kiểm actual access/endpoint khi gặp hai trường hợp đó; App recommendation không bị chặn bởi khác biệt docs. [PAT limitations](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens#fine-grained-personal-access-tokens-limitations), [Checks endpoint](https://docs.github.com/en/rest/checks/runs#list-check-runs-for-a-git-reference).

## Private target-project và điều kiện provisioning thật

1. **Xác định account sở hữu các repo cần App ghi.** Nếu Crew repo và target-project cùng owner, App “Only on this account” có thể đủ; nếu khác owner, private App chỉ cài vào account tạo App không đủ. Visibility “Any account” cho cài nơi khác, nhưng không làm target-project private thành public. Chưa biết owner/access của target-project, không invent. [Install your own App](https://docs.github.com/en/apps/using-github-apps/installing-your-own-github-app).
2. **Đúng người có install rights thực hiện lúc provisioning.** Personal account có thể cài; organization owner có thể cài. Repository admin có thể cài khi App không xin organization/Repository administration permissions và org không cấm; nếu thiếu rights cần owner actual. Nhu cầu này là conditional account action, không phải xác nhận sản phẩm mới mỗi bước. [Install requirements](https://docs.github.com/en/apps/using-github-apps/installing-a-github-app-from-a-third-party#requirements-to-install-a-github-app).
3. **Register App và cấp selected repo/grants thực tế.** Registration cho tắt webhooks nếu chỉ dùng authentication; Crew local có thể polling, không bị buộc dựng public webhook server/OAuth login. Đây là đề xuất vận hành; latency/rate-limit/poll cadence còn phải kiểm theo session contract. [Register App](https://docs.github.com/en/apps/creating-github-apps/registering-a-github-app/registering-a-github-app).
4. **Provision key vào credential boundary trusted.** App owner tạo key, bảo quản/rotation; gateway lưu App ID, installation ID, repository ID và reviewer Human ID không phải secrets. Chỉ secret key/token được chuyển qua kênh local bảo mật khi tới bước này, không dán lên Issues. Chưa có App/account/key/token thực tế.
5. **Nếu App installation thực tế bị policy từ chối,** thu bằng chứng exact denial rồi so bot access với owner; nếu cả hai bị chặn, frontier là access decision. Không thay PAT scope hoặc chuyển sang Human-authored PR để né D17.

## Token lifecycle và storage local macOS

**Cơ chế đề xuất, chưa implement:** trusted gateway ký App JWT rồi xin installation token theo installation/repo binding; giữ token trong memory, dùng `expires_at` để mint lại trước operation. App JWT `exp` tối đa 10 phút; không lấy thời hạn JWT làm thời hạn installation token. [JWT docs](https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/generating-a-json-web-token-jwt-for-a-github-app).

Không tái thử mù PR/create Issues/merge khi token/network lỗi: đọc lại trạng thái side effect và run record rồi mới quyết định retry. Đây là thiết kế suy ra từ ADR-0001 và OUTPUT đã chốt, không phải promise GitHub về idempotency. Dùng opaque token, không phụ thuộc độ dài 40 ký tự: GitHub ghi rollout installation-token format mới từ 27/04/2026. [Token generation docs](https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/generating-an-installation-access-token-for-a-github-app).

**Storage proposal:** secret store local do gateway kiểm soát; macOS Keychain là ứng viên cần prototype. GitHub docs chỉ chứng minh credential helper `git-credential-osxkeychain` có lưu credentials, không chứng minh worker cùng user không gọi helper/đọc item. Không tự gọi Keychain là OS boundary đã đủ. [macOS Keychain credential helper](https://docs.github.com/en/get-started/git-basics/updating-credentials-from-the-macos-keychain).

Key không vào repo/worktree, command args, logs/transcript, child env hoặc inherited credential helper của worker. Git subprocess của gateway nhận credential qua đường riêng, không cấy token vào remote URL persist hoặc trả token cho ACP. Đây là proposal kiểm ở [confinement](https://github.com/Riso-application-factory/zed-ai-crew/issues/18) và [gateway](https://github.com/Riso-application-factory/zed-ai-crew/issues/19). GitHub khuyên bảo vệ private key, không hard-code; env storage kém hơn key vault vì process đọc env có thể lấy persistent authentication. App key không tự hết hạn nên rotation và revoke còn là trách nhiệm thật. [Private key guidance](https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/managing-private-keys-for-github-apps).

Không khẳng định GitHub App RSA key có thể import thành key Secure Enclave không xuất được, hoặc Keychain không cần access-control/signing configuration: nghiên cứu này chỉ dùng GitHub sources và không đọc credential/storage thực tế. Việc chọn store/OS enforcement phải có evidence riêng; token type đổi không tự giải quyết sandbox.

## Coordinator có thể resolve gì

Research [Xác định cơ chế GitHub identity riêng cho Crew](https://github.com/Riso-application-factory/zed-ai-crew/issues/21) có thể hoàn tất bằng kết luận: **installation-token mechanism đáp ứng identity/capabilities cốt lõi theo docs và là technical recommendation; bot PAT fallback có điều kiện; không dùng Human user token để tạo PR.** Ghi đề xuất vào canonical ticket, link report và đưa provisioning/runtime checks sang [confinement](https://github.com/Riso-application-factory/zed-ai-crew/issues/18), [gateway](https://github.com/Riso-application-factory/zed-ai-crew/issues/19) hoặc prerequisite có scope rõ. Không gán recommendation thành “Human đã chọn GitHub App”.

Chưa cần hỏi lại lựa chọn tách identity đã confirmed. Khi cần thật sự tạo/cài App hoặc cấp repo access, thu owner/repo/install-rights cần thiết và nêu đúng account action; nếu owner khác/hạn chế policy tạo trade-off mới, hỏi tại frontier đó. Nghiên cứu không cho quyền provisioning và không yêu cầu production approval để đọc docs.

**Runtime return criteria còn thiếu:** App-authored PR actor khác Human; Human actual review đúng head; Git push/Issues/merge trên private fixture với đúng grants; expired/revoked tokens/keys/installation suspend có xử lý đúng; token/key không tới worker/logs; direct bypass bị deny; kết quả merge read back. Không có phép kiểm nào trong danh sách đã chạy.

**Validation thực sự:** đọc nguồn primary GitHub ngày 2026-10-11; API docs hiện minh họa version `2026-03-10`; đối chiếu canonical decision và contract. Không provision App/bot/key/token, đọc secret contents, gọi GitHub mutations/provider, chạy tests, mở PR, push hoặc sửa source. Chỉ tạo report này; Coordinator chịu cập nhật tracker canonical.
