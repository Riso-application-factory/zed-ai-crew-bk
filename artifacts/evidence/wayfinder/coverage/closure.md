## Common recipe contract

Each recipe is a versioned definition in the trusted registry under #9/#11. Orchestrator proposes a finite graph using known steps/capabilities; code validates inputs, dependencies, authority, evidence and OUTPUT. The labels in the tables are semantic steps to synthesize into the spec, **not imported old33-cycle taxonomy or executable definitions already implemented**. Branch/rework creates valid occurrences/attempts under configured bounds; no arbitrary worker text becomes executable authority.

Every instance binds project/repo/privacy, canonical input selectors/content revisions, subject/Story/criteria, plan/definition/role/skill/model/profile/policy/source versions, required capabilities and effect scopes. Native Thread/Session/run/attempt identities stay distinct. Source/binding missing/corrupt/unresolved → explicit prerequisite error before effects; source drift → invalidate affected closure and replan within authority. Metadata/progress comments outside selectors do not silently change spec version.

Common gates apply to all rows: current authority/data destination and #7 private no-training conditions; actual capability/source admission on each enabled native/host path; durable intent/reservation before mutation; independent applicable evidence; scope/OUTPUT bounds; original-US requirement binding. No new account/billing/provider/environment authority from a recipe. Human questions include context, example, trade-off and recommendation; only dependent choices wait, independent work with current rights continues.

Result schema separates execution state, findings/verdict and OUTPUT evaluation. Failed/cancelled/partial/uncertain/inconclusive must retain actual facts and next action. Native end-turn/worker exit0/model text/elapsed timeout are not OUTPUT. A bounded assessment may finish with inconclusive findings when that is the requested report; a requested fix/deploy/migration/recovery cannot become achieved by writing a report.

The shared foundation C01–C05/C07–C11 applies to all scenarios; C06 is mandatory for S05/S07/S08 and conditional whenever another session explicitly includes a code change. C05 means the product supports the three required ACP integrations, not that every recipe must call all three or spend on unneeded workers. Discovery/prototype/report sessions do not silently become implementation sessions.

## Common failure / rework seams

- **Missing Ready/input/capability:** reject affected dispatch with exact missing source/field/permission; propose the relevant prerequisite/refine route, keep existing run/decisions. No fake fallback to default model/store/native direct tools.
- **Quota/capacity/provider error:** retain binding and exact backend error, pause only affected work, report context/evidence/next action. No silent provider/account/billing switch; no diagnosis of a platform notice as a code defect without evidence. Retry admission and external effects obey operation semantics, not a generic “try again”.
- **Human absence/decision:** questions stay in chat with context/example/trade-offs/recommendation; dependent path waits, independent current-authorized paths continue. PR review remains GitHub. No Crew Approve/Re-run buttons.
- **Drift/rework/conflict:** use source selectors/versions, affected dependency closure, actual conflict/review/check facts; technical replan within existing intent/rights needs no repeated approval. New scope/OUTPUT/authority trade-off needs actual Human answer.
- **Cancel/loss/uncertainty:** durable intent and reservations, owner/callback identity and late facts; no blind replay/rollback/claim stopped. Protected artifact and physical effect-scope terminal follow ADR0004; current gateway/external target uncertainty cannot be bypassed by a new directory/attempt.
- **Verification failure:** rework candidate/implementation with fresh applicable checks and review; skip/missing/zero-tests/partial evidence not green. Required source/host/native/toolchain route missing stays delivery blocker, not a scenario cut.
- **Data/retention/delete failure:** #7 boundaries/30-day rule and actual controlled-store inventory, partial status and recovery evidence; no public target-derived payload without actual allowed scope/redaction or false server-erasure result.
- **No authority/third-party prerequisite:** prepare exact safe evidence/question/request without external communication by default. Operational permissions/project facts come from the actual session; planning does not grant them.
