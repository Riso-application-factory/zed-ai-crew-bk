# Bounded command survival across controller loss

Status: **verified prototype answer for #48; full confinement #18 remains OPEN**. The destination is still specification readiness for the product, not production delivery. Sources: [#48 question](https://github.com/Riso-application-factory/zed-ai-crew/issues/48), [actual sole-controller loss](https://github.com/Riso-application-factory/zed-ai-crew/issues/18#issuecomment-6163928716), [#47 correlation](https://github.com/Riso-application-factory/zed-ai-crew/issues/47#issuecomment-6162148744), [#44 supervisor](https://github.com/Riso-application-factory/zed-ai-crew/issues/44#issuecomment-6154015658), [#45 registered guardian](https://github.com/Riso-application-factory/zed-ai-crew/issues/45#issuecomment-6160790140). Human launcher choice A / ADR-0002 and all three mandatory ACP providers remain unchanged.

## Actual candidate and ownership

The new public fixture moves actual adapter/helper Popen handles, nonce/ACP-call/epoch registry, HTTP gateway, upstream synthetic model fixture and ACP publisher/receiver into a separate surviving supervisor process. A thin controller process holds a private inherited authority channel, requests one fixed generation, and polls its status. An external observer registers the actual controller PID on its separate private control channel. This is a different executed topology from the killed sole-controller fixture, not an implied upgrade of the original prototype.

Actual installed ACP/native binaries remain unchanged. The installed native `run_command` permission is approved by the public client and translated to native rejection; only the existing separate fork-free command helper executes under its fixed OS floor. Exact admitted argv/exec input, profile/program/source/policy, current registry nonce/ACP session/call/native observation and owner epoch are checked. Caller-selected launcher fields, wrong epoch and duplicate `begin` requests are rejected on actual private controller RPCs in the final revision. No authority/control descriptors enter the adapter or helper. This is a fixture-controlled admission contract, not full private authority provenance or loaded-image attestation.

The survivor is the actual direct parent/wait owner of adapter and helpers. It integrates the #45 guardian's live registered adapter/native NOTE_EXIT watches and sticky unknown-member/error fence for the tested known graph. Native kernel termination is not native wait/reap. Registrations precede helper effects. There is no MCP relay in this command topology and no claim of arbitrary descendant mediation.

On controller channel EOF, the epoch becomes unavailable before retirement. Helper handles survive the controller, so the survivor kills and directly collects paused commands rather than orphaning them. Helper direct waits, adapter direct wait, and registered engine termination acknowledgments precede generation quiescence and new activation. An observer-only gate deliberately pauses retirement to test a real second controller while an old engine remains live. Another control holds acceptance of actual kernel exits: replacement stays rejected despite adapter reap/known kernel exits until ACK acceptance is released.

Helper admission and actual HTTP model handoff are serialized against the EOF fence. Publication uses an explicit generation check and a single terminal identity gate. Normal shared model/client output equality is retained. A test-only recovery packet uses ACP status `failed` and describes `interrupted-before-effect`, `interrupted-after-effect` or `unknown`; it never claims rollback. Before-effect classification is supported only by the pinned public worker's explicit wait gate plus direct kill/reap, not by absence of an effect file alone. Uncertain arbitrary-command outcomes are not validated by these tests.

Gateway/upstream ownership also survives controller loss, while old-epoch forwarding is fenced. This does not make two receiver deliveries atomic or prove client application acknowledgment.

## Validation and retained limits

`antigravity-command-survivor-verify.py` checks **406 expected observations across 10 actual runs**: **29 helper direct reaps, 18 adapter direct reaps, 36 registered kernel engine exits, 42 prompts/42 delivered terminal packets, 22 shared completed result comparisons**. The supervisor-loss run is excluded from successful reclaim counts. Each surviving generation's helper/adapter/kernel facts precede its lease release; fresh activation follows old quiescence. Terminal identities are unique, actual source pins match recorded revisions, outside canaries stay unchanged, public effects and outside/engine/env/FD controls are recorded, and no orphan cleanup is needed when the survivor remains alive.

Initial p1 n1/h1 evidence is retained as weaker serialization evidence. p2 adds serialized helper admission, actual HTTP handoff and final publication, plus one-shot begin admission. Final source n2/h2/r2/m2 adds genuine invalid-controller-RPC probes and conservative before-effect versus unknown classification. These are source revisions, not invented failed provider iterations.

The first verifier v1 incorrectly required a live unreclaimed engine at the early replacement attempt in every loss case. Actual m1 evidence shows the supervised generation driver can already have reclaimed its engine while the old lease gate still prevents replacement. The revised verifier checks live-engine replacement denial specifically in h1/h2/a1, and old-lease denial in all owner-loss cases. The old verifier is retained; it is not a candidate protection failure. Inherited generation-report worker fingerprints/limits refer to #47 ancestry; actual diagnostic worker bytes are captured in each run's public worktree and pinned through the source/configuration, not attributed to those inherited fields.

All tracked fixture actors are absent after cleanup. For s1, external SIGKILL/PID absence is explicitly not a direct-parent reclaim proof. Old #44/#45/#47 and sole-controller loss archives were verified exact and unchanged after this investigation. No raw vendor prompts/catalogue or binary payloads are archived; installed binaries are fingerprinted only.

Run evidence verification with `python3 artifacts/evidence/wayfinder/confinement/antigravity-command-survivor-verify.py`. To reproduce, use the driver with `--case normal|helper|receipt|model|held-ack|survivor-loss --label <new-unused-label>`. A prior run directory is never overwritten.

## Answer and return to confinement

**Yes within this public fixed fork-free command/registered adapter-native graph and only while the supervisor survives.** Retaining actual child handles and result state outside the controller closes the exercised orphan/reclaim and lost-result cases; truthful recovery preserves already-delivered model facts rather than pretending they were undone. This is a bounded planning answer, not a selected production architecture or confirmed customer-facing recovery policy.

No instantaneous stop at physical SIGKILL is promised: the recorded fence is private channel EOF, and leases remain unavailable to replacement until reclaim. Arbitrary effects racing with EOF, unpaused long commands, PTY/async/daemon/build trees, arbitrary descendants, pre-admission/full policy algebra, private six-source effective provenance, provider conversation restoration, real inference/compaction, native internal denial versus gateway repair, durable supervisor restart/reclamation and production service/maintenance remain unresolved. Separate cancellation/resume #20 is unchanged.

Return to assigned #18 without a new Human permission gate. Inspect the supported native history/continuation/restoration surface and where gateway-repaired results differ from actual native state; reproduce a precise public behavior or supported-interface gap before proposing the next prerequisite. Do not duplicate #20 or select a production frontend. The map remains draft / awaiting decision; collapse to spec only when the remaining in-scope decisions/fog are exhausted.
